# camera-live notes (in progress)

Chain (live, not p+0xF08): p=u32[0x2AA0D0|0x2AA0D4], cam=u32[p+0xF08], dir=u32[cam+0x198] stride 0x90, target=p+0x660.
VU packet source: slot=0x01CE2270+u32[cam+0x174]*0xC0, copied at FUN_00244fc8 0x2454c4. Only FUN_00244e88 (identity init) and FUN_00244fc8 form that address. FUN_00244fc8 also reads cam+0xE0 (0x40) and cam+0x120 (0x40), scales xyz by 0x3C000000 (0.0078125) at 0x245088, multiplies by the slot, and puts both into the VIF packet. Packet buffer is the return of FUN_00232a60 (0x180 bytes), not a fixed address.
Look-at FUN_00193800 writes only Y of 0x2D27D0/E0/F0. a2/a3 of that call are unread.
Eye FUN_0018e1e0: bnel at 0x18e3c4 is NOT taken. preHw is 0 (player0) and 21 (player1); the compare at 0x18e314 is against 1000. Both fall into 0x18e3cc. sqrt.s at 0x18e2d4 is sqrt.s f1,f0 (word 0x46010044) and the C++ matches. Not a decode bug.
Dumps: [camlive] in the override (eye/look/upload) and logs/grok/camera_live_snap.py (PCSX2). Fields: dir90, xform80, target, cam words, cam16, camE0 (32 floats from +0xE0), slot 4x4, basis 0x2D27D0, p0/p1.
Build: out/grok-camera-live via tools\grok_build.cmd camera-live. Probe DumpAt default 62,68,74,80; shots add +8s so the last PINE snap is not raced.
Gate (logged on eye ENTRY as preflag/preTa/preTb/preHw, and after the call as flag/ta/tb): flag u32[0x35A48C] from FUN_00197b48. If flag==0 and tableA[idx]==0 (0x35A1D0+idx*4), FUN_0018e1e0 beqz at 0x18e244 goes to 0x18fcf0 and does not write the body. A finished body stores tableB[idx]=1 and tableA[idx]=0 at 0x18fcdc/0x18fcec, so a post-call read of tableA is not the entry token. preHw = lh *(*(cam+0x1C8)+0x50), compared to 1000 at 0x18e314: equal takes the one mul into dir+0x40 (0x18e350) then bnel 0x18e3c4 skips to 0x18fca8; not equal falls into 0x18e3cc.
FUN_0018de48 writers: FUN_00182430 (0x182758, 0x182784, idx=lh fighter+0x3C, a1=1; that function runs ~3 times/run), FUN_00198f68 0x199cd4, FUN_001c15a8 0x1c2838, FUN_00244a10 0x244a38 (idx=*(cam+0x174), a1=1, only if *(cam+0x180)!=0). Only caller of FUN_00244a10 is FUN_002035c8 at 0x203ba0.
VU packet: FUN_00244fc8 early-out if *(cam+0x1BC)==0 (0x245030) or *(slot+0x84)==0 (0x245044). 0x2454c4 lq's the slot 4x4 (s4) into the packet at +0x20; the cam+0x120/cam+0xE0 product is copied from the stack (0x2454e8+). s84 is now logged.
World mul FUN_001d5b48 matches L and R (camera-live-5 stdout 159-164). It does not create the 16k; L already holds it (ra 0x182b60, L translation 16557.8945 2150 -15337.9355).
Player XZ writer: FUN_0025f7b0 0x25fabc swc1 f0,0(s0) and 0x25facc swc1 f0,8(s0). f0 is lwc1 from (*(s2+4))+0 and +8 (0x25fab4 / 0x25fac8). 0x25fab8 stores 0 to player+4. Same XZ is then copied to player+0xE00 by 0x25fb58/0x25fb60, then FUN_00186810 copies it to +0xE40.
Root Y: FUN_00186810 0x18697c/0x186980 = player+4 + FUN_00189d18's f0 + float[0x358258]. c7018=1150 both platforms. Ours call 1 (pxyz 0): f0=409.6154, Y=1559.6154. Ours call 3 (pxyz already 16557.8945, 0, -15337.9355): f0=1000 exactly, Y=2150. FUN_00189d18 returns f20, loaded from 0x359320 (0x189d34) and replaced only at 0x189f98 when a collision plane height wins. a0 of that call is player+0xE40 (0x186888). Plane list head is u32[0x1B3FE90+0x1C]; FUN_002148b0 returns the constant 0x1B3FE90.
